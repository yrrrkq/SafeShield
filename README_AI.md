## 2. 계층별 기술 스택

| 계층 | 기술 | 역할 |
|---|---|---|
| Frontend | React 18, Vite, Tailwind CSS | 사이드바 + 대시보드형 UI, 실시간 분석 결과 렌더링 |
| Backend API | FastAPI, Uvicorn (ASGI), Pydantic | REST/WebSocket API 서버, 요청 검증 |
| 동적 분석 엔진 | Playwright (Python, async) | 실제 헤드리스 브라우저로 URL 접속, 리다이렉트·다운로드 관찰 |
| 정적 분석 엔진 | `zipfile`, `hashlib` (Python 표준 라이브러리) | 다운로드된 APK의 SHA-256 해시 계산, AndroidManifest.xml 권한 파싱 |
| AI 위협 분석 | Google Gemini API (google-genai SDK) | 텍스트 의미 분석 + 샌드박스 기술 증거를 결합한 다차원 위협 리포트 생성 |
| 온체인 합의 계층 | Python 인메모리 시뮬레이션 (`blockchain.py`) | 4개 오라클 노드의 2/4 멀티시그 합의 모델 |
| B2C 보호 계층 | Python 인메모리 시뮬레이션 (`mock_bank.py`) | 위협 탐지 시 가상계좌 송금 즉시 차단 |
| 실시간 통신 | FastAPI WebSocket (`/ws/broadcast`) | 위협 확정 시 클라이언트 실시간 푸시 |

## 3. 핵심 파이프라인: URL 하나가 분석되는 전체 과정

```
[1] 사용자 입력
    프론트엔드에서 SMS 텍스트 + URL 입력
    → POST /api/sandbox/analyze

[2] 실제 브라우저 실행 (sandbox.py)
    Playwright가 실제 Headless Chromium을 실행
    → 실제 page.goto()로 대상 URL 접속 시도
    → 접속 실패 시: 정직하게 threat_score=0, verdict="UNREACHABLE" 반환 (가짜 데이터 없음)
    → 접속 성공 시:
        - HTTP 3xx 리다이렉트를 response 리스너로 실제 추적
        - page.inner_text("body")로 실제 DOM 텍스트 추출
        - 자동 파일 다운로드 이벤트(Download)를 실제 인터셉트

[3] 정적 분석 (파일이 다운로드된 경우에만)
    - 다운로드된 바이트를 hashlib.sha256()으로 실제 해싱 (0x 접두 bytes32 포맷)
    - zipfile로 열어 AndroidManifest.xml에서 위험 권한 문자열 실제 검색
    - try/finally로 임시 파일 반드시 삭제 (샌드박스 격리)

[4] AI 위협 분석 (ai_classifier.py)
    - 추출된 실제 텍스트 + 샌드박스가 관측한 실제 기술적 증거 (리다이렉트 횟수, 다운로드된 권한 목록)를 함께 Google Gemini API (gemini-3.6-flash)에 전달
    - Gemini가 다음을 구조화된 JSON으로 분석:
        · 피싱 유형 분류        · 사칭 대상 기관
        · 사용된 사회공학 기법   · 텍스트-기술증거 상관관계
        · 위험 점수 (0~20)      · 권고 조치
    - API 키 미설정/오류 시 → 키워드 매칭 기반 스코어링으로 자동 폴백

[5] 하이브리드 점수 산출
    동적 행위(최대 40점) + 정적 권한(최대 40점) + NLP/AI 문맥(최대 20점) = 100점
    → 80점 이상: CRITICAL_MALWARE 판정

[6] 즉각 대응 (mock_bank.py)
    점수 ≥ 80 → 데모 가상계좌 lock_account() 실제 호출 (30분)
    → 이후 해당 계좌의 모든 이체 시도는 코드 레벨에서 실제로 거부됨
    (UI 표시가 아니라 attempt_transfer() 함수 내부에서 실제 검증)

[7] 온체인 위협 등록 (blockchain.py, 별도 비동기 트랙)
    threat_score ≥ 80 → propose_threat()로 멀티시그 제안 생성
    → 4개 오라클 노드(KISA/AhnLab/경찰/금감원) 중 2곳 이상 승인 시 확정
    → 확정되면 /ws/broadcast로 전체 클라이언트에 실시간 전파
```

## 4. AI 활용 방식

- **입력 신호 이원화**: (1) 페이지/SMS의 실제 텍스트 의미, (2) 샌드박스가 실측한 기술적 텔레메트리(리다이렉트 수, 실제 다운로드된 파일의 위험 권한)를 함께 LLM에 제공
- **출력**: 단일 라벨이 아니라 사칭 대상, 사용된 사회공학 기법, 텍스트-기술증거 간 정합성 분석, 권고 조치를 포함한 **분석 리포트**
- **비용 효율 및 높은 접근성**: Google Gemini API (gemini-3.6-flash)의 무료 티어(Free Tier)를 활용하여 API 호출 비용 문제 없이 안정적인 다차원 리포트 생성
- **안전한 폴백**: API 키 미설정 시 자동으로 키워드 기반 규칙 엔진으로 전환 — 서비스 가용성을 AI 의존적으로 만들지 않음

## 6. 테스트/데모 인프라

실제 피싱 사이트에 접속시킬 수 없으므로(윤리적·법적 문제), **`test_target_server.py`**라는 별도의 무해한 픽스처 서버를 구성했습니다.

- 4가지 시나리오(`/parcel`, `/wedding`, `/loan`, `/police`) 각각 실제 HTTP 302 리다이렉트를 발생시킴
- "악성 APK"로 위장한 파일은 **실행 코드가 전혀 없는 순수 ZIP + 텍스트 매니페스트**로, 실제 기기에 설치조차 불가능함
- 이를 통해 실제 Playwright 파이프라인(접속→리다이렉트→다운로드→해싱→정적분석→AI분석→점수산출→계좌잠금)이 **가짜 데이터 없이 end-to-end로 실제 동작**하는 것을 검증

## 9. 실제 vs 시뮬레이션 — 한눈에 보는 요약

| 구성요소 | 상태 |
|---|---|
| Playwright 브라우저 자동화 | ✅ 실제 동작 |
| SHA-256 해싱 | ✅ 실제 다운로드된 바이트 기준 실제 계산 |
| APK 정적 권한 분석 | ✅ 실제 ZIP/매니페스트 파싱 |
| Gemini AI 위협 분석 | ✅ 실제 API 호출 (키 필요, 없으면 키워드 폴백) |
| Mock Bank 송금 차단 | ✅ 실제 코드 레벨 강제 (UI 표시용 아님) |
| 온체인 멀티시그 합의 | ⚠️ 구조/로직은 실제와 동일하나, 실제 블록체인에 배포되지 않은 시뮬레이션 |
| 은행 계좌 연동 | ❌ 실제 금융기관 연동 없음 (자체 가상 원장) |
| 피싱 사이트 데이터 | ❌ 실제 피싱 사이트 대신 자체 제작한 무해한 테스트 픽스처 사용 |
